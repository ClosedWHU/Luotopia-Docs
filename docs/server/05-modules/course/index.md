# 课程服务概览

课程服务是 Luotopia 的核心业务之一，旨在通过数据聚合为学生提供透明、真实的教学信息参考。

## 包含的功能专题

1.  **[课程评价系统](./review.md)**: 
    学生对课程质量的感性描述与量化评分。
2.  **[课程给分统计](./course_grades.md)**: 
    匿名的真实给分提交与绩点分布趋势分析。
3.  **[教务数据同步](../timetable.md)**: 
    从校内系统抓取最新的课程列表与排课信息。

## 2. 数据聚合策略 (Statistical Aggregation Strategy)
 
为了确保课程评分的准确性与最终一致性，系统采用 **原子化全量重算** 策略，而非简单的增量累加。
 
### 2.1 统计更新流 (`UpdateCourseStats`)
当课程评价状态变更为“已核准”时，系统会基于该课程的所有合规样本触发重算逻辑：
 
```sql
SELECT 
    COUNT(*) as total_count, 
    AVG(rating) as avg_rating, 
    AVG(difficulty) as avg_difficulty, 
    AVG(workload) as avg_workload
FROM reviews 
WHERE course_id = ? AND is_approved = true;
```
 
### 2.2 核心设计考量
- **精度漂移防护**: 增量更新在处理并发写入或事务回滚时，容易产生微小的浮点数精度漂移。全量重算能确保聚合数据始终与原子记录完全对应。
- **状态流转兼容**: 评价记录可能被管理员撤销、隐藏或重新核准。全量重算天然支持这些状态变更，无需编写复杂的增量冲销逻辑。
- **查询加速**: 聚合后的结果冗余存储于 `courses` 表的主干字段中。这使得在展示课程列表时，系统能以 O(1) 的复杂度获取平均评分，大幅提升响应速度。

## 3. 常见问题 (FAQ)

**Q: 频繁的重算是否会造成数据库压力？**
A: 不会。对于单个课程的重算操作，数据库会利用 `course_id` 索引快速过滤记录。在高频写入场景下，系统通过内存队列实现了防抖（Debounce）处理，确保同一课程在短时间内仅重算一次。

**Q: 为什么某些评价不计入统计？**
A: 只有通过 AI 自动审核或人工审核（`is_approved = true`）的评价才会参与重算。处于待审状态或已被标记为违规的内容会被自动剔除。
