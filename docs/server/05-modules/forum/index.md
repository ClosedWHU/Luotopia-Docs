## 排序算法：热度评分 (Hotness Score)

Luotopia 论坛的信息流不是简单的按时间倒序排列，而是基于一个加权衰减算法来动态计算帖子的“热度”，确保最优质、最及时的内容优先展示。

### 1. 评分公式
系统内部通过 `calculateHotScore` 函数计算分值：

$$Score = \frac{Engagement}{(AgeHours + 2)^{1.3}}$$

其中 **Engagement**（参与度）的计算逻辑为：
- **点赞 (Upvote)**: +4 分
- **评论 (Comment)**: +6 分
- **收藏 (Favorite)**: +8 分
- **踩 (Downvote)**: -3 分

### 2. 设计考量 (Design Considerations)
*   **权重差异**: 
    *   **评论 > 点赞**: 评论代表了更深层次的用户参与，因此权重更高。
    *   **收藏最高**: 收藏行为代表了内容的长期价值，被视为最高质量的互动。
    *   **负反馈惩罚**: 踩操作会直接抵消正向得分，配合“管理员审核阈值”，可实现社区内容的自我净化。
*   **重力衰减 (Gravity Decay)**: 
    *   分母中的 `(AgeHours + 2)^1.3` 是典型的重力因子。
    *   随着时间（小时）推移，分数值会呈指数级下降。这保证了即便是极高互动的旧帖，最终也会让位给有潜力的新帖，维持社区的鲜活度。

### 3. 实现细节 (`internal/forum/repo/interaction.go`)
系统并不会在每次请求时重新计算所有帖子的热度。
- **触发更新**: 当用户执行点赞、评论或收藏操作时，会同步调用 `refreshHotScore` 更新该帖子的分值。
- **持久化**: 最终得分存储在 `posts` 表的 `hot_score` 字段，配合数据库索引实现极速查询。

## 4. 常见问题 (FAQ)

**Q: 热度分是否会实时更新？**
A: 会在每次互动行为后触发。系统通过数据库字段冗余确保了查询时无需实时计算。

**Q: 为什么有些新帖虽然没有评论但排在前面？**
A: 这是重力因子的作用。新发布的帖子在 `AgeHours` 较小时具有极高的加权优势，以便获得初始曝光。
