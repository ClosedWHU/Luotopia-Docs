# 全局错误码规范

Luotopia Server 使用统一的错误响应格式。

## 1. 响应格式
所有错误响应均遵循以下结构：
```json
{
  "code": 400,
  "message": "错误详细说明",
  "request_id": "req-xxxx-yyyy"
}
```

## 2. 错误码定义
错误码通常与 HTTP 状态码保持一致，但在特定业务逻辑下会有细分。

### 2.1 通用错误
| 错误码 | 说明 | 建议处理方式 |
| :--- | :--- | :--- |
| 400 | 请求参数错误 (Bad Request) | 检查输入格式 |
| 401 | 未认证 (Unauthorized) | 重新登录或提供有效 Token |
| 403 | 权限不足 (Forbidden) | 联系管理员提升权限 |
| 404 | 资源不存在 (Not Found) | 确认资源 ID 或 URL |
| 429 | 请求过于频繁 (Too Many Requests) | 稍后重试（触发速率限制） |
| 500 | 服务器内部错误 (Internal Server Error) | 记录 `request_id` 并反馈给后端 |

### 2.2 业务状态码
部分 401 响应会携带细分的业务代码，用于引导客户端逻辑：

| 业务码 | 说明 | 建议处理方式 |
| :--- | :--- | :--- |
| 1002 | Token 已过期 (Token Expired) | 执行静默刷新 (Refresh Token) |
| 1003 | Token 已废弃或已登出 | 引导用户重新登录 |

### 2.3 身份模块 (20xxx)
| 错误码 | 说明 |
| :--- | :--- |
| 20001 | 用户名或密码错误 |
| 20002 | 用户已被禁用 |
| 20003 | 邮箱已被注册 |
| 20004 | SSO 状态已过期 |

### 2.3 论坛模块 (30xxx)
| 错误码 | 说明 |
| :--- | :--- |
| 30001 | 内容包含违禁词（AI 拦截） |
| 30002 | 帖子已锁定，无法评论 |

## 3. 如何调试
当遇到错误时，请在响应中获取 `request_id`，并在服务器日志中搜索该 ID 以获取详细的堆栈信息。
