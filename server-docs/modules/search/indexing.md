Luotopia 业务搜索基于 **PostgreSQL 全文检索**（及可选扩展），**无需**独立搜索集群。实现位于 `internal/domains/search`。

> 本文说明**能力与运维边界**。查询构建、索引 DDL、缓存键以实现为准；联调以 OpenAPI 的 search / suggest 路径为准。

## 1. 能力概览

| 能力 | 说明 |
|------|------|
| 作用域搜索 | 如课程、教师、评价等 scope（名称以 API 为准） |
| 关键词 | 多词查询；分词与配置语言（如 `simple` / jieba）由部署决定 |
| 过滤 | 部门等过滤条件与 scope 组合 |
| 建议 (suggest) | 输入补全类接口 |
| 可选 | `pg_trgm`、pgvector 混合检索（镜像与配置开启时） |

## 2. 原理（概念）

PostgreSQL FTS 使用：

- **tsvector**：文档侧预处理表示  
- **tsquery**：查询侧表达式  
- **`@@`**：匹配  

业务层将用户输入转为查询，再在对应表/字段上匹配。具体字段拼接与配置字典以实现为准。

## 3. 部署依赖

- 推荐使用仓库提供的 DB 镜像（含常用扩展）。  
- 索引多在搜索服务初始化时尝试创建；迁移/启动失败时查日志。  
- 扩展名与 config 见 [环境搭建](../../development/setup.md)、[Docker](../../deployment/docker.md)。

## 4. 调用约定

- HTTP 路径与查询参数：**OpenAPI**。  
- 客户端应限制 `limit`、使用分页，避免过大结果集。  
- 查询词过宽（如单字「课程」）可能导致结果过多——应用层与产品侧应引导更具体关键词。

示例（路径以实例为准）：

```bash
# 健康与联调
curl -s "http://localhost:6262/health"
# 搜索参数见 OpenAPI；多数环境需 Bearer
```

## 5. 故障排查（现象级）

| 现象 | 可能方向 |
|------|----------|
| 无结果 | 词不在数据中；scope 错误；软删除过滤；鉴权失败 |
| 结果偏少 | 分词/配置语言与数据语言不一致；索引未建 |
| 偏慢 | 缺索引、结果集过大、复杂过滤——查慢查询与初始化日志 |

**不要**在公开文档中依赖固定 `EXPLAIN` 模板作为运维手册；生产诊断用内部 runbook。

## 6. 缓存

可选应用层缓存热门查询；TTL 与 key 为实现细节。变更数据后的失效策略以实现为准。
