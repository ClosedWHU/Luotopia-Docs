对用户生成内容（论坛帖、评论等）做检查，支持敏感词与策略动作。实现与词库路径以部署为准。

> 公开文档只描述**能力与接入约定**；不公开词库内容、远程词库 URL、完整匹配算法实现。

## 能力

| 能力 | 说明 |
|------|------|
| 检测 | 判断文本是否命中策略词/规则 |
| 处理建议 | 如警告、遮罩、拒绝、转人工（枚举以实现为准） |
| 分类 | 政治、色情、广告、辱骂等业务分类（可配置） |
| 字典更新 | 支持重载；更新源与周期为运维配置，不进公开文档 |

## 接入约定

- 发帖/评论等写路径在 **service 层** 调用审核，不在 http 处理器内散落硬编码词表。  
- 命中后的产品行为（拦截、隐藏、仅通知）由业务域决定。  
- 审核结果可记审计日志；**日志不得输出完整敏感词表或用户隐私原文策略以实现为准**。

## 配置（项名级）

部署侧通常配置：

- 词库文件路径或内置资源  
- 各类别默认动作与严重级别  
- 是否启用自动更新  

具体 key 见 `config` 样例与代码；**生产词库与密钥不进 git / 不进公开文档**。

## 不要做

- 在客户端做「唯一」审核（可被绕过）  
- 在公开文档粘贴真实敏感词列表或可下载的私有词库地址  
- 依赖未文档化的内部 HTTP 调试接口作为正式审核 API
