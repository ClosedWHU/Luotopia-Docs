## 访问与身份

- 论坛和课程评价均为登录可见、登录可写。未认证请求不得读取帖子、评论、课程评价或聚合给分。
- 论坛普通用户界面显示论坛昵称；管理员审核界面显示经过权限审计的身份信息。公开 API 不返回学号、邮箱、真实姓名或评价作者 ID。
- 课程评价始终匿名。后端保存用户 ID 只用于资格验证、反作弊、本人编辑删除和合规追溯。

## 昵称

- 用户首次设置论坛昵称不受冷却影响。
- 冷却策略：短期内多次修改昵称的冷却时长逐级增加；具体天数为实现细节。
- 每次修改记录旧值、新值和时间，供后台实名审核。客户端只展示下一次可修改时间，不在公共内容中回溯昵称历史。

## 掩体板块

- `boards.is_shelter = true` 的板块为掩体；后台只能由管理员设置。
- 发帖和评论使用同一帖内稳定的随机别名。一个用户在同一主题的主帖和所有评论均显示同一个别名；不同主题不复用别名。
- 掩体帖具有有效期（`expires_at`）；到期后帖子和评论均不再从普通 API 返回，也不能继续评论。有效期长度以实现为准。
- 后台通过帖子作者 ID、评论作者 ID、主题别名映射和身份域资料进行全实名审计；这些字段不得暴露给普通用户。

## 评价资格

**服务端不接收教务 Cookie / 密码。** 评价与给分资格由服务端按内部风控规则授予（基于已核验的修读记录）。

- 创建、编辑、删除、互动和举报评价均要求 Luotopia 登录。
- 发布评价 / 提交给分前，服务端要求当前用户与目标课程存在**已核验**的修读记录；核验与风控规则为实现细节。
- 修读结果（outcome）：`scored` | `absent` | `withdrawn`（有分、缺考、中期退课）。

## 资格导入

1. 用户登录并绑定武大身份后，调用 `POST /api/v1/user/review-eligibility/sync`（需登录；字段以 OpenAPI 为准）。服务端自行完成核验，全过程**不接收、不存储教务 Cookie / 密码**。
2. 核验通过的修读记录写入私有成绩 / 完成记录，并按课号映射解析到内部 `course_uid`。
3. 未映射课程码可返回供运营补映射；**禁止**仅靠课名模糊匹配绕过。
4. 同步响应仅返回资格与映射统计字段（如 `eligible_course_uids`、`unmapped_course_codes` 与计数）；不返回其他用户数据。

## 给分与审核

- 给分样本与评价资格复用同一已核验修读记录；同一用户、课程、教师、学期 upsert。
- 低样本时聚合被抑制（阈值为实现细节）：只返回 `sample_count` 与不足状态（`sufficient`）。
- 读模型：`GET /api/v1/course/grades/view/{course_uid}?teacher_uid=`（自有 + 可选 Ham 补充）。
- 新评价待审核；编辑后重新待审。公开列表仅已通过内容。
- 举报要求登录、理由枚举和去重；管理员操作记审计日志。
