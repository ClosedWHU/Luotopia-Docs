# 论坛与课程评价身份策略

## 访问与身份

- 论坛和课程评价均为登录可见、登录可写。未认证请求不得读取帖子、评论、课程评价或聚合给分。
- 论坛普通用户界面显示论坛昵称；管理员审核界面显示经过权限审计的身份信息。公开 API 不返回学号、邮箱、真实姓名或评价作者 ID。
- 课程评价始终匿名。后端保存用户 ID 只用于资格验证、反作弊、本人编辑删除和合规追溯。

## 昵称

- 用户首次设置论坛昵称不受冷却影响。
- 90 天内第 1 次修改后冷却 7 天，第 2 次修改后冷却 14 天，第 3 次及以后冷却 30 天。
- 每次修改记录旧值、新值和时间，供后台实名审核。客户端只展示下一次可修改时间，不在公共内容中回溯昵称历史。

## 掩体板块

- `boards.is_shelter = true` 的板块为掩体；后台只能由管理员设置。
- 发帖和评论使用同一帖内稳定的随机别名。一个用户在同一主题的主帖和所有评论均显示同一个别名；不同主题不复用别名。
- 每个掩体帖的 `expires_at` 为创建后 24 小时。到期后帖子和评论均不再从普通 API 返回，也不能继续评论。
- 后台通过帖子作者 ID、评论作者 ID、主题别名映射和身份域资料进行全实名审计；这些字段不得暴露给普通用户。

## 评价资格（客户端成绩上传）

**服务端不使用用户 Cookie 请求学校教务。** 资格来自用户登录后，由客户端从校园侧拉取的完整成绩数据上传。

- 创建、编辑、删除、互动和举报评价均要求 Luotopia 登录。
- 发布评价 / 提交给分前，服务端必须在 `course_completion_records` 中找到当前用户与目标课程的可信记录。
- 合法 outcome：`scored` | `absent` | `withdrawn`（有分、缺考、中期退课）。
- **唯一可信来源**：`client_transcript`（客户端完整成绩上传）

## 凭据同步实施

1. 用户在客户端完成校园登录 / 打开成绩页，**客户端本地**获取成绩列表（服务端永不接收或转发教务 Cookie）。
2. 客户端调用 `POST /api/v1/user/transcript/sync`（需登录；字段以 OpenAPI 为准）。
3. 服务端写入私有成绩/完成记录、解析 `course_uid`、授予评价资格；可选贡献匿名给分样本。
4. 未映射课程码可返回供运营补映射；**禁止**仅靠课名模糊匹配绕过。
5. 同步响应仅返回：可评价 `eligible_course_uids`、映射计数、未映射课号列表；不返回其他用户数据。

## 给分与审核

- 给分提交复用同一课程完成凭据；同一用户、课程、教师、学期 upsert。
- 聚合统计最低样本数为 5。低于阈值时只返回 `sample_count` 与不足状态。
- 读模型：`GET /api/v1/course/grades/view/{course_uid}?teacher_uid=`（自有 + 可选 HAM 补充）。
- 新评价待审核；编辑后重新待审。公开列表仅已通过内容。
- 举报要求登录、理由枚举和去重；管理员操作记审计日志。
