文档站（`docs.whu.sb` / `Luotopia-Docs`）**对外开源**；客户端、服务端、官网业务代码**默认闭源**。  
目标：贡献者与对接方能**按约定正确集成**，无法仅靠文档**复刻闭源实现**。

用户指南（`/user`）偏产品操作；本页约束 **`/client` 与 `/server` 开发文档**。

## 1. 三层深度

| 层 | 写什么 | 不写什么 | 示例 |
|----|--------|----------|------|
| **A. 契约** | 对外行为、协议、错误语义、配置项名 | 内部算法、私有密钥、未公开接口 | `Authorization: Bearer`；`/api/v1/*` 默认需登录 |
| **B. 边界** | 谁做什么、数据流到哪、禁止事项 | 具体爬取步骤、第三方 HMAC 密钥 | 教务 Cookie 不上业务服；更新走官网非 `system` |
| **C. 结构** | 目录职责、分层规则、扩展点名称 | 完整类图、逐函数实现、商业策略细节 | `features/whu_auth` vs `luotopia_auth`；`presentation` 不写 API 路径 |

默认写到 **A + B**；**C 点到为止**（目录与规则，不贴实现）。

## 2. 允许写（推荐）

- **公开 API 契约**：路径前缀、鉴权方式、OpenAPI 为权威；文档只做摘要并链到 OpenAPI。  
- **架构决策与边界**：双账号、App 直连校园 vs 业务服、官网更新/热更新与业务服分离。  
- **客户端结构约定**：feature-first、Riverpod、WebView 边界、SnackBar root messenger 等**可重复的工程规则**。  
- **本地联调**：模拟器 `10.0.2.2`、端口样例 `6262`、`customServerUrl` 步骤（**无**生产地址与密钥）。  
- **配置项名**：`security.jwt_secret`、`server.port` 等——写「必须配置 / 生产必换」，**不写真实值**。  
- **失败模式**：401 刷新、prerelease 404、热更新「本地缺失」等**现象级**说明。  
- **占位与 WIP**：标明能力状态，避免读者以为已开源实现。

## 3. 禁止写（硬红线）

| 类别 | 说明 |
|------|------|
| **密钥与凭证** | JWT 生产密钥、GitHub/CF token、第三方 API Key、Ed25519 **私钥**、签名公钥若仅用于闭源校验可只写「内置公钥校验」而不贴值 |
| **武大/第三方逆向细节** | 完整请求链、隐藏参数、签名算法实现、硬编码 `secret`、可复现的 PoC |
| **未公开接口** | 未进 OpenAPI 的内部路径、管理后门、调试开关的生产用法 |
| **可复刻的闭源核心** | 整段解析脚本、完整热更新 canonical 实现、防滥用策略阈值与绕过方法 |
| **基础设施敏感面** | 生产域名清单以外的内网拓扑、真实 DB 连接串、监控 Basic Auth 密码、私有镜像凭据 |
| **用户数据样例** | 真实学号、姓名、成绩、Cookie、token 样例（用 `user@example.com` / 占位符） |

> [!CAUTION]
> 「写在文档里方便自己」不等于可以公开。闭源仓库的 README / 内部 Notion 可以更细；**进 `user-docs` / `client-docs` / `server-docs` 前先过本节红线**。

## 4. 怎么写才「能参考开发」

用 **契约 + 检查表 + 反例**，代替 **贴源码**：

```markdown
### 扩展校园解析（公开写法）

1. 在 `ParserNames` 增加名称，并尽量提供 `DefaultScripts` 兜底。  
2. 远程脚本经官网 manifest 下发；校验失败则回退内置。  
3. UI：无缓存时显示「本地缺失」，禁止因 throw 卡死加载。  

不要：在文档中粘贴完整 JS 解析器或签名私钥生成步骤。
```

| 读者问题 | 公开文档应回答 | 应指向闭源的 |
|----------|----------------|--------------|
| 如何登录业务 API？ | Bearer、刷新、白名单概念 | 具体 JWT claims 内部约定（若未公开） |
| 课表从哪来？ | App 直连教务 + 本机存储 | 教务抓包细节 |
| 如何发版更新？ | 官网 releases 接口行为 | CI 密钥、签名机流程 |
| 如何加子应用？ | 目录、路由、认证类型、错误态清单 | 某校内系统完整协议 |

## 5. 源码路径怎么写

- **可以**：`features/hot_update`、`internal/domains/identity`（模块级导航）。  
- **谨慎**：精确到行号、未发布分支路径、仅内部 monorepo 才有的绝对盘符。  
- **不要**：要求读者「打开闭源文件第 N 行」才能完成集成；集成步骤必须在文档 + OpenAPI 内闭环。

## 6. 分区建议篇幅

| 分区 | 深度 |
|------|------|
| `/user` | 操作与安全预期；无内部模块名堆砌 |
| `/client` | 工程约定 + 边界 + 联调；**无**第三方协议复现 |
| `/server` | 部署配置项、安全模型、模块职责；OpenAPI 为字段权威；**无**生产密钥与滥用细节 |

内部架构计划、执行清单与排期**不进入**公开文档仓；确需公开时，只保留已公开决策，删除未公开排期、人员、漏洞细节。

## 7. 发布前检查清单

- [ ] 无真实密钥、token、连接串、私钥  
- [ ] 无完整第三方签名/爬取可复现步骤  
- [ ] 业务字段以 OpenAPI 为准，文档未发明未实现接口  
- [ ] 示例账号/密码为假数据  
- [ ] 闭源实现用「行为 + 目录」描述，而非大段源码粘贴  
- [ ] 用户文档未暴露仅开发者使用的危险开关（或已标明风险）

## 8. 发现泄露时

1. 从文档站删除或改写。  
2. 轮换已暴露的密钥 / token。  
3. 如需，在闭源仓内部通告，**不要**在公开 changelog 重复密钥内容。
