本指南旨在规范 Luotopia 项目文档的语言风格、结构组织及排版要求，确保所有技术文档具备生产级的专业性与一致性。

## 1. 语言风格与基调

### 1.1 专业性

- **禁用口语化修饰词**：严禁使用“实战版”、“技术干货”、“避雷针”、“点我直达”等非正式表述。
- **中性叙事**：避免使用第一人称（如“我觉得”、“我建议”），应使用客观叙事（如“系统设计采用...”、“建议配置为...”）。
- **准确定义**：所有的技术术语应与源码保持一致。

### 1.2 简洁性

- **杜绝冗余**：不要在标题或正文中添加情绪化词汇（如“炸裂”、“深度分析”）。标题应直接反映内容，如“系统架构分析”而非“深度解析系统架构干货”。
- **直接切入**：每一篇文档应在第一段明确说明该文档解决的问题或描述的对象，不进行多余的背景渲染。

### 1.3 标点与用词

- 中文正文使用全角标点（：，。「」）；代码、字段名与配置键保留原文。
- UI 元素与术语引用使用直角引号「」，不使用直引号 ""。
- 同一概念全站使用同一术语：两套账号体系统一用「账户」（武大账户 / 珞家账户）；「其它」统一写作「其他」；校车统一写作「校巴 / 校园巴士」。

## 2. 文档结构规范

每一篇技术文档应尽可能遵循以下逻辑层次，禁止采用“前言 + 补丁”的结构。

1.  **概览 (Overview)**: 描述该组件/模块的功能边界、核心目标及与系统其他部分的关系。
2.  **设计原理 (Design Principles)**: 阐述“为什么要这样设计”，包含核心算法、协议选择或架构考量。
3.  **技术实现 (Implementation Details)**: 提供源码级的分析、流程图、配置示例或 API 定义。
4.  **最佳实践与约束 (Best Practices & Constraints)**: 
    - **融合叙事**: 将开发中的经验教训直接融合进正文的逻辑流程中。
    - **FAQ 机制**: 针对常见的配置误区或集成难点，在每个重点章节的末尾提供 FAQ 列表。

## 2.5 开源文档站与闭源代码

文档站公开、业务代码闭源时，深度控制见 **[公开文档边界](./public_docs_policy.md)**。

摘要：写 **契约、边界、目录约定**；不写 **密钥、可复现逆向、未公开接口、完整闭源实现**。

## 3. 排版与格式要求

### 3.1 标题层级

- front matter `title` 是唯一标题来源；正文**不写** `# H1`（站点以 `title` 渲染页首 H1，避免双重声明漂移）。
- 使用 `## H2` 和 `### H3` 进行逻辑分层，避免超过四级的标题嵌套。
- 标题内不使用 `**加粗**` 等行内标记；多文件分区内不使用跨文件连续编号（如「4.5」）。

### 3.2 代码块与引用

- **语言标记**：所有代码块必须指定语言（如 `bash`, `go`, `javascript`）；无高亮需求的纯文本使用 `text`。
- **告警框 (Alerts)**：使用 GitHub 风格告警语法（站点已装 `remark-github-blockquote-alert` 渲染，GitHub 网页阅读时同样生效），合理使用以强调关键信息。
    - `> [!NOTE]`: 背景信息。
    - `> [!IMPORTANT]`: 必须遵守的操作。
    - `> [!CAUTION]`: 可能导致数据丢失或安全风险的操作。
    - 若使用 Docusaurus 原生 `:::` 语法：本站启用 `future.v4`，自定义标题必须写成方括号形式（如 `:::note[标题]`）；`:::note 标题` 会整块渲染为字面文本。

### 3.3 链接、命名与 URL

- 引用项目内其他文档时，请使用相对路径（含 `.md` 扩展名）。
- 引用源码文件时，请指向具体的路径，并简要说明其职责。
- 文件名使用 `snake_case`；公开 URL 使用 kebab-case：多词文件在 front matter 声明 `slug: kebab-name`（旧下划线 URL 由 `docusaurus.config.ts` redirects 兜底）。
- 跨分区链接使用 `pathname:///server/...` 形式，并以 slug 化后的 kebab URL 为准。

## 4. 反面案例对照

| 错误示例 | 推荐修改 |
|------|------|
| `### 2.4 技术干货：从 AI 置信度到风险评分` | `### 2.4 AI 风险评分机制与阈值设计` |
| `## 5. 开发建议与避雷针` | `## 5. 最佳实践与常见集成难点` |
| `# 业务接口调用指南 (实战版)` | `# 业务接口调用规范` |
| `- **干货**: 允许我们精准定位...` | `- **实现价值**: 该监控项支持精准定位...` |
