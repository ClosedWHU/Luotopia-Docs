错误响应的实际形状与 `business_code` 集合以 `internal/platform/errors`、中间件与 **OpenAPI** 为准。本文是错误语义的唯一汇总页；其他文档只链接至此，不重复维护错误码表。

## 响应格式

失败响应为 **problem+json**（字段说明见 [HTTP 注册规范 · 错误契约](./http_api.md#3-错误契约)）：

```json
{
  "status": 401,
  "title": "Unauthorized",
  "detail": "Invalid username or password",
  "code": "UNAUTHORIZED",
  "business_code": 1004,
  "details": {},
  "request_id": "req-xxxx-yyyy"
}
```

| 字段 | 说明 |
|------|------|
| `status` | HTTP 状态码 |
| `code` | 粗粒度错误类（下表） |
| `business_code` | 客户端分支用稳定整数（见分段表） |
| `detail` | 可展示短文案；5xx 统一为固定内部文案 |
| `details` | 可选附加信息；仅 4xx 返回，内部字段会被过滤 |
| `request_id` | 请求追踪 ID |

## 错误类（`code`）

| 标识符 | HTTP 状态码 | 说明 |
|------|------|------|
| `BAD_REQUEST` | 400 | 请求参数格式错误或校验未通过 |
| `UNAUTHORIZED` | 401 | 身份认证失败或令牌无效 |
| `FORBIDDEN` | 403 | 权限不足，无法执行该操作 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 资源冲突（如用户名已存在） |
| `INTERNAL_SERVER_ERROR` | 500 | 服务器内部逻辑错误 |
| `DATABASE_ERROR` | 500 | 数据库操作异常 |

个别错误会显式覆盖 HTTP 状态（如限流用 429、依赖不可用用 503）；以响应中的 `status` 为准。

## 业务码分段（`business_code`）

业务码用于引导客户端执行特定逻辑（如静默刷新令牌或跳转登录）。

### 身份与认证（1000 - 1999）

| 业务码 | 说明 | 建议处理方式 |
|------|------|------|
| 1000 | 未认证 | 跳转登录 |
| 1001 | 令牌无效 | 引导用户重新登录 |
| 1002 | 令牌已过期 | 执行静默刷新（refresh token） |
| 1003 | 用户不存在 | 仅用于资料 / 头像等资源查询（HTTP 404） |
| 1004 | 凭据 / 密码错误 | 提示检查账号密码 |
| 1005 | 权限被拒绝 | 提示联系管理员 |
| 1006 | 需要 MFA | 进入 MFA 挑战流程 |
| 1007 | 邮箱后缀不被允许 | 提示更换邮箱 |
| 1008 | 邮箱已存在 | 提示更换邮箱或直接登录 |
| 1009 | 邮箱未验证 | 引导完成邮箱验证 |
| 1010 | 账号被禁用 | 提示联系管理员 |
| 1011 | 密码策略不满足 | 按策略提示修改密码 |
| 1012 | 需要武大身份 | 引导绑定武大账号 |
| 1013 | 武大账号已绑定 | 提示该武大身份已被使用 |
| 1014 | 验证校验失败 | 重新获取 / 提交验证码 |
| 1015 | 认证尝试受限 | 提示稍后再试 |
| 1016 | 需要修改密码 | 引导改密流程 |

> [!IMPORTANT]
> 登录接口返回**统一凭据错误**：无论账号不存在还是密码错误，均返回 HTTP 401 + 业务码 1004 的固定文案，不区分用户是否存在（防用户枚举）。客户端不应尝试据此判断账号是否注册。

## 调试与日志

当客户端遇到非预期的错误时：

1. **记录 Request ID**：所有 `request_id` 均会记录在服务端日志中，反馈问题时附上。
2. **查看 details**：4xx 响应可能包含字段校验失败信息；内部敏感字段已在服务端过滤。
