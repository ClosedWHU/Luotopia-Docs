> [!NOTE]
> 两家均采用客户端硬编码盐值的 HMAC/SHA256 请求头签名；盐值随小程序包分发，可被离线提取（弱点类别：客户端信任边界失守）。本页仅保留机制概述与弱点评估，签名构造公式、字段顺序与复现步骤已移入私有仓 `whu-ebike-re`。

## 请求封装层

全站业务请求经 `common/vendor.js` 中的统一封装层发出，职责包括：

- 合并公共 body 参数（平台、traceId、deviceId、租户 ID、客户端版本）与业务参数；
- 计算请求头签名并附加时间戳头与签名方案版本头（见下）；
- 认证头分流：登录/刷新接口使用 OAuth2 客户端认证（由包内硬编码租户凭据派生，派生细节存档于私有仓），其余接口携带 Bearer accessToken；
- 开锁链路接口额外附加同盾设备指纹头（见下）；
- 从[域名池](./overview.md)取当前网关域名，失败时剔除域名并在 60s 窗口内重试（默认 3 次）；
- 统一处理 token 过期静默刷新与重放（见[认证与会话](./auth.md)）、错误码分流与日志上报。

## 请求头签名（`_s`）

全站唯一的请求签名机制：对最终 JSON body 串、时间戳与租户签名盐做 SHA256，结果放入请求头；时间戳另以明文头携带。

弱点评估：

- 签名盐 `platformSign` 为 64 位十六进制硬编码常量，完全暴露在客户端包内（值已脱敏），**签名可离线伪造**；
- 多套环境（含 DEV/TEST/UAT）的签名盐全部随包分发（弱点：测试环境同样缺乏签名防护，见[概述](./overview.md)）；
- 时间戳无服务端时钟校验迹象，客户端仅有 60s 重放拦截且只对本地延迟生效（弱点类别：重放防护不完整）。

签名串拼接公式、公共参数字段顺序与伪造复现步骤存档于私有仓 `whu-ebike-re`。

## 文件上传的签名

`uni.uploadFile` 通道的签名与请求层同源，但公共参数以表单字段传递（覆盖对象为 formData 的序列化串）；另有一个走普通 JSON 请求层的上传接口。构造细节存档于私有仓 `whu-ebike-re`。

## 同盾设备指纹 `deviceToken`

开锁链路（骑行权限校验与网络/蓝牙开锁等少数接口，端点枚举存档于私有仓）在签名之外附加第三方同盾插件生成的设备指纹头 `deviceToken`：App 启动即初始化并预热，取不到时同步预热后重试；openid 以 MD5 摘要传入插件。插件合作方配置参数存档于私有仓。blackbox 内部算法在微信插件内、不在包内，无法静态分析（见[其他发现](./findings.md)）。

## juju 第三方广告独立签名

juju 广告投放/事件接口不走业务签名层，使用**另一套硬编码 appId/appSecret 的 SHA256 独立签名**（弱点类别：第三方凭据硬编码于客户端，可离线提取后伪造广告请求；appId/appSecret 值已脱敏）。签名串构造细节存档于私有仓 `whu-ebike-re`。
