知音出行的短信验证码登录已被运营方关闭（见[认证与会话](./auth.md)），而其余登录方式都必须由微信在官方小程序内签发一次性授权码——第三方应用拿不到。因此本应用的知音功能需要你**先在微信小程序里正常登录一次**，再把那次会话的令牌导入进来。

> [!CAUTION]
> 本文只涉及**抓取你自己的账号、在你自己的设备上**产生的流量。请不要在他人设备、他人账号或公司管控设备上操作。用第三方客户端驱动账号可能违反运营方服务条款，风险自负。

## 你需要准备

- 一台能安装根证书的电脑或手机（见下方平台说明）
- 一个 HTTPS 抓包工具：推荐 [mitmproxy](https://mitmproxy.org/)（免费、跨平台、可脚本化）；也可用 Charles、Fiddler、HTTP Toolkit、Reqable
- 你自己的微信，且已在知音出行小程序里登录过

## 各平台路线

| 平台 | 路线 | 难度 |
|---|---|---|
| **Windows / macOS 电脑上的微信** | 在电脑微信里打开知音小程序，用 hosts 劫持 + mitmproxy 反向代理截取 | 中 |
| **iPhone** | 手机 WiFi 代理指向电脑上的 mitmproxy；或用 Shadowrocket / Quantumult X 的 MITM 模块 | 中 |
| **Android（无 root）** | HTTP Toolkit / Packet Capture / HttpCanary 等 VPN 型抓包 App | 低—中，但**微信可能不信任用户安装的证书**，失败率最高 |
| **Android（有 root）** | 把抓包工具的证书装进系统证书目录，再配 hosts 或 iptables 重定向 | 高，成功率也最高 |

> [!NOTE]
> 本项目实测通过的是 **macOS + 电脑端微信**这条链路。其余平台按各自系统机制推导，首次使用请自行验证：能同时抓到普通 App 的 HTTPS 明文、却抓不到微信的，通常就是证书信任级别不够（Android 7+ 应用默认不信任用户证书）或存在证书固定。

### 通用步骤

1. 安装 mitmproxy，先跑一次 `mitmdump` 让它生成证书（在 `~/.mitmproxy/`，Windows 为 `%USERPROFILE%\.mitmproxy\`）。
2. 按上表选择的方式，把该证书安装到设备/系统的**受信任根证书**里。
   - iOS 装完描述文件后，还必须去「设置 → 通用 → 关于本机 → 证书信任设置」手动开启**完全信任**——这是最常漏的一步。
3. 让微信的流量经过抓包工具：
   - 手机路线：WiFi 代理指向电脑 IP + mitmproxy 端口。
   - 电脑微信路线：把业务域名写进 hosts 指向 `127.0.0.1`，并用 `mitmdump --mode reverse:https://<真实IP>:443 --listen-port 443 --set keep_host_header=true --set ssl_insecure=true` 反向代理到真实服务器。这条路线的好处是**不依赖客户端是否遵守系统代理**，也能与 Clash/Shadowrocket 之类的 TUN 模式共存。
4. 打开知音小程序，进一次主页（有登录态的请求即可）。
5. 在抓包工具里筛选发往 `ebike-client-prod2.xiaoantech.com` 的请求。

## 要抓哪两个值

| 值 | 在哪里 | 作用 |
|---|---|---|
| **accessToken** | 任意一条已登录业务请求的请求头 `Authorization: Bearer …` | 当下调用接口用；它是 JWT，可本地解出过期时间 |
| **refreshToken** | 登录或刷新那一刻的 token 端点**响应体** | 让本应用自动续期；**没有它，accessToken 一过期就要重抓** |

refreshToken 只出现在登录/刷新的响应里，日常业务请求中不带。如果没抓到，在小程序里登出再登入一次即可。

## 导入本应用

**设置 → 共享电单车 → 知音出行 → 高级：导入令牌**

- 访问令牌一栏容忍多种粘贴形态：裸令牌、`Bearer eyJ…`、整行 `Authorization: Bearer eyJ…`、带引号或带换行都可以。
- 刷新令牌选填，但强烈建议填。
- 点「导入并验证」后，应用会先调用一次用户信息接口确认令牌有效——**无效令牌不会被保存**，也不会覆盖你已有的绑定。
- 成功后会提示访问令牌的过期时间，届时如已填 refreshToken 会自动续期，否则需重新抓取。

## 安全与善后

> [!WARNING]
> **抓完请把抓包工具的根证书从信任库里删掉。** 一个被系统长期信任的 MITM 根证书，等于给这台设备上**所有** HTTPS 流量开了一个常驻后门：任何持有对应私钥的进程都能冒充任意网站。这一步比抓包本身更重要。

- 抓包产生的流量文件（mitmproxy 的 `.mitm`）包含你的令牌、手机号、openid 与实时位置，**不要提交到任何仓库、不要发到群里、不要贴进工单或截图**。
- 逐项还原环境：关系统代理 → 删 hosts 条目 → 停掉代理进程 → 刷 DNS 缓存 → **删除根证书** → 重连 VPN。
- 令牌等同于账号凭据：持有者可以解锁车辆、发起一卡通支付。只在自有设备上保存，不要分享给他人。

完整的平台命令、参数含义、还原清单与排障判据存档于私有仓 `whu-ebike-re` 的 `docs/mitm-wechat-miniprogram.md`。
