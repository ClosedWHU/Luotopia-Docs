核心为 `common/vendor.js` 中的用车 mixin（被 `pages/map` 与分包 `pagesSub/precycling`、`pagesSub2/riding` 混入）。

## 扫码入口与用车确认页（precycling）

`wx.scanCode`/启动参数 → 解析二维码 URL：域名必须命中 ext 的 `qrDomain`（知音 = `ebike-zhiyin.xiaoantech.com`），车辆号按「查询参数值 → 末段路径 base64 解码为纯数字 → 路径中 ≥4 位数字」顺序提取。随后跳转用车确认页 `pagesSub/precycling/precycling.js`（子页 instructions 为用车说明）：

- **扫码埋点**：上报扫码数据（车辆号、定位、是否真实扫码——区分真扫码与页面跳转、定位授权状态）；
- **页面数据**：按车辆号拉取车辆详情（含服务区），并行拉取广告位与首页运营位；支付召回场景时提示并播寻车铃；
- **确认用车**：进入开锁主流程（权限校验/网络/蓝牙开锁见下）；
- 预约用车（发起/取消/详情）在地图页，precycling 不含预约接口调用。

## 开锁前权限校验（网络）

网络开锁前调用骑行权限校验接口（**请求头带同盾 deviceToken**，见[请求与签名](../signing.md)），请求携带服务区、车辆号、用户标识、定位、协议类型与可选的微信支付分单号（请求体字段清单存档于私有仓 `whu-ebike-re`）。

响应返回校验状态与一组 **action/tips 码**，驱动前端弹窗与跳转：未实名、人脸核验（3 分钟内免重复）、实名复核、服务区绑定失败、黑名单、隐私协议、用车资格（押金/免押/押金卡）、校园一卡通绑定、已在骑行、他人预约车、信用分限制、余额不足、车辆未备案、未支付订单、钱包欠款等；tips 侧含远程开锁确认、支付分失败提示、押金自动代扣确认、头盔弹窗。完整码表存档于私有仓 `whu-ebike-re`。

## 网络开锁

开锁主流程（含微信支付分免押分支，见下文）调用网络开锁接口（电单车/普通单车分支两条路径；**均带 deviceToken**），请求携带定位、车辆号、用户标识、预约单号与若干可选开关（自动临停、支付分免押渠道、优惠车活动、押金自动代扣确认、安全骑行弹窗状态；字段清单存档于私有仓）。

成功 → 重启进入骑行页；**错误码 `17012`（车辆弱网/指令超时）自动降级蓝牙开锁**；`15047` 未备案换车、`15030` 余额不足弹窗。开锁成功后可触发寻车语音。

## 蓝牙开锁（弱网兜底 / onlyBluetooth 强制）

蓝牙开锁流程（协议帧与指令码细节见[蓝牙（BLE）指令层「加密」](../crypto.md)，已移入私有仓）：

1. 拉取蓝牙还车配置（是否需蓝牙道钉检测）；
2. 道钉检测：按锁类型（TBIT/小安）走对应协议栈的检测指令，结果（beacon 地址/电量/经纬度等）压入检测结果数组；
3. 蓝牙权限校验（带 deviceToken）：提交车辆号、定位、用户标识与道钉检测结果；
4. 获取蓝牙 token（两类锁各有服务端下发通道，TBIT 优先用车辆详情内 token）并经对应协议栈执行开锁指令；
5. 结果上报服务端（开锁上报接口）→ 成功进入骑行页。

## 还车 / 临时停车 / 头盔锁

1. **还车前置**：还车权限校验返回是否可还、还车类型、罚金、人脸通过态、头盔锁延时等；人脸未通过时还车需先人脸核验；头盔锁刚开启需等待 5 秒；特定还车类型引导拍照还车（`pagesSub/applyReturnEbike`）或拍照引导页。
2. **网络还车**：电单车/普通单车分支两条路径，成功结算进入支付页；配置可强制先走网络还车。
3. **蓝牙还车**：经对应协议栈执行关锁指令（指令码存档于私有仓），随后向服务端上报还车结果（请求携带订单、车辆、定位与拍照/人脸/充电桩等状态位；字段清单存档于私有仓）。
4. **拍照/AI 还车审核**：还车审核资格查询 → 创建审核并还车；AI（VLM）识别还车照片；是否在停车点判定；部件匹配（含临停场景）；四色车拍照校验。
5. **临时停车**：临停 → 临停中解锁继续骑行 / 结束临停；次数限制检查；蓝牙侧有对应临停/结束上报；另有临停解锁配置。
6. **头盔锁**：开/关头盔锁接口；头盔照片上传绑定订单；头盔弹窗素材来自 ext 配置。
7. **调度/寻车（用户侧）**：寻车语音、开锁后铃声、运营寻车通道；调度费免除接口。

## 微信支付分免押（开锁链路内嵌）

开锁主流程在开锁前处理三种支付分状态（相关接口均为服务端签名，客户端仅透传）：

- **需确认押金**：查询确认渠道 → 创建确认订单，服务端返回 `wx.openBusinessView` 所需的 mch_id/package/timestamp/nonce_str/sign 等参数，客户端原样拉起支付分确认视图；确认单号随后续权限校验上传；
- **未开通但已授权**：查询授权记录 → 创建支付分订单得单号，开锁请求携带支付分免押渠道标识；
- **首次开通**：授权申请后 `wx.navigateToMiniProgram` 跳转微信支付分小程序（appid `wxd8f3793ea3b935b8`）开启授权；回跳场景由 App onShow 捕获写入全局状态；
- **完结/取消**：订单完结（扣款）、查询、取消与解约接口齐备。

## 骑行页轮询节奏（pagesSub2/riding/riding.js）

- **骑行信息轮询 = 每 10 秒**，页面加载/显示时先立即调一次；另有轻量静默刷新变体。
- **乱序防护**：每次请求携带递增序号，回调校验序号不匹配则记日志丢弃。
- **异常分支**：特定错误码直接忽略本轮；失败且订单已结束 → 停表、清理路线，1 秒后进入结算支付页；获取失败弹窗确认后回地图页。
- **本地秒表**：每秒累加骑行时长并执行临停计时；初始化成功后以服务端时长校准。
- 初始化并行拉取：骑行卡信息、还车配置链路、卡推荐、学习免罚配置、骑行中报修配置（见[报修/违章接口](../api/repair.md)）；生成场景级 traceId 串联还车埋点。
