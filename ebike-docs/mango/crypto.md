> 请求头签名机制（mg-sig/mg-ts/mg-sk/mg-eyt）、签名弱点评估与未签名上传通道见[请求签名](./signing.md)。密钥/IV 构造与输出编码链细节已移入私有仓 `whu-ebike-re`。

## 设备信息 mg-dvi（AES 上行加密）

| 项 | 值 |
|---|---|
| 算法 | `AES-256-CBC`，`PKCS7` 填充 |
| 密钥/IV | **硬编码常量**（32 字符 key + 16 字符 IV，值已脱敏）。**固定 IV，不随请求变化** |
| 明文 | 设备信息 JSON：固定端点标识 + 定位（经纬度/精度/速度等）+ 系统信息（型号/系统/屏幕/电量/字号等）+ 运营区 ID |
| 输出位置 | HTTP header `mg-dvi`（编码链细节存档于私有仓） |

弱点评估：

- **key 与 IV 均为随包分发的常量**，`mg-dvi` 只是编码而非保密：等同明文设备指纹（每请求携带精确 GCJ02 经纬度、电量、设备型号、系统版本、屏幕尺寸、字号设置、区域 ID，见[隐私与合规观察](./findings.md#隐私与合规观察)）；
- **实现竞态**：系统信息经异步回调采集，但明文在同一同步执行流里立刻序列化——除首个请求外系统字段才被逐步回填，`mg-dvi` 内容在同一会话内**不稳定**，服务端不可能强校验其完整性（实现观察）。

## 响应体解密（joker）

响应 JSON 顶层存在真值字段 `joker` 时，`body` 字段为密文，客户端以**另一组硬编码 key/IV**（与上行不同组，值已脱敏）做 AES-256-CBC 解密后得到真实业务 JSON。

要点：

- 方向为服务端 → 客户端（**下行**）；上行 body 从不加密；
- 客户端**没有任何开关**去请求加密响应，`joker` 完全由服务端决定（可能对特定接口/特定灰度用户开启），已还原代码中找不到哪些接口会被加密；
- **弱点**：解密结果连同完整 URL 直接 `console.log`，配合包内 `app.json` 的 `"debug": true`，真机 vConsole 可直接读到全部明文业务数据（见[调试开关](./findings.md#调试开关)）。

## 硬编码密钥/常量汇总

客户端包内硬编码的密钥与业务常量**类别**如下（所有值与定位信息——文件/函数/行号——均已移除，存档于私有仓 `whu-ebike-re`）：

| 类别 | 用途 | 风险 |
|---|---|---|
| HMAC-SHA256 签名密钥（32 字符，已脱敏） | `mg-sig` 请求签名 | 高：可离线伪造签名 |
| AES-256 key/IV（上行组，已脱敏） | `mg-dvi` 设备信息加密 | 高：常量 key/IV，等同明文 |
| AES-256 key/IV（下行组，已脱敏） | `joker` 响应体解密 | 高：同上 |
| 第三方地图 token（32 位十六进制，已脱敏） | geovisearth API（**明文放 query**） | 中 |
| IM 客服渠道号（已脱敏） | 承满点在线客服 | 低 |
| 业务 licenseId（`5a13efac…` 等，已脱敏） | 武大信息授权协议、骑行规则视频已看标记 | 低 |
| 占位 ID / 插件埋点常量 | 非业务 | 低 |

**未发现**：RSA / SM2 / SM4、MD5 / SHA1 业务用法、动态密钥协商、密钥白盒、`wx.getRandomValues`、时间戳对齐/nonce、一机一密。`utils/crypto-js.js` 打包了 CryptoJS 全套算法，但业务只引用 `HmacSHA256` + `AES` + `enc.Base64/Hex/Utf8` + `mode.CBC` + `pad.Pkcs7`（其余为 tree-shaking 缺失导致的体积浪费）。
