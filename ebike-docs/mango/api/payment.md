## 支付 / 充值 / 押金 / 卡券能力类别

支付为**服务端签名的微信 JSAPI**：下单接口返回 `wx.requestPayment` 五元组，客户端零加工透传；支付结果一律以服务端校验接口的 `paid` 为准（success/fail 双分支都延时查询）。charge 报文结构、请求参数与 openid 客户端可控等弱点评估见[支付与押金流程](../flows/payment-deposit.md)；完整清单存档于私有仓 `whu-ebike-re`。

存在以下能力类别的接口：

- **余额**：充值（也用于补付未付订单）；
- **支付结果校验**：按支付单 ID 查询（全仓库 14 处调用，统一延时查询模式，部分入口带重试计数）；
- **押金**：交押金（金额取运营区配置）；
- **免押/卡券购买**：免押卡、免押+通勤套餐、通勤卡（周/月/季/年）、季卡（key 名存在 buy→bug 拼写错误）、新版骑行卡商品、包车卡（扫码后、开锁前购买）；
- **退款**：退押金原因列表（覆盖前端硬编码的 8 条默认原因）；
- **死代码残留**：微信统一下单（外部商户端点）与 `wxPay` 两个 key 仅定义未调用——小程序不可能直连商户 API（需商户证书），确认为历史残留。
